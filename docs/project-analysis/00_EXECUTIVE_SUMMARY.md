# الملخص التنفيذي

## 1. ما هو هذا المشروع؟

**BATTECHNO LMS** منصة إدارة تعلّم (Learning Management System) لإدارة برامج **الشهادات المصغّرة (micro-credentials)** بالشراكة مع جامعات أردنية. تجمع المنصة تسليم المناهج، الحضور، التقييم، ضمان الجودة، الاعتراف الأكاديمي، إصدار الشهادات، والتدريب الميداني في نظام واحد متعدد البوابات.

**الثقة:** Confirmed — `README.md`، وصف الحزم `battechno-lms-api` / `battechno-lms-web`.

## 2. من هم المستخدمون؟

| الفئة | الدور التقني | ماذا يفعلون؟ |
|-------|--------------|--------------|
| إدارة البرنامج / النظام | `super_admin`, `program_admin`, … | إعداد الجامعات، المناهج، المجموعات، الجودة، الشهادات |
| أعضاء هيئة التدريس | `instructor` | الجلسات، الحضور، التقييم، الأدلة، التدريب الميداني المعيَّن |
| الطلاب | `student` | التسجيل، الدورات، التسليمات، التدريب الميداني |
| مراجعو الجامعات | `university_reviewer` | طلبات التسجيل، الاعتراف، الشهادات، تقارير التدريب |

**الثقة:** Confirmed — `frontend/src/constants/roles.js`، `backend/scripts/lib/baselineCatalog.js`.

## 3. القيمة التجارية الرئيسية

تمكين BATTECHNO والجامعات الشريكة من تشغيل برامج شهادات مصغّرة مع:

- التحقق من هوية الطلاب عبر **نطاقات البريد الجامعي**.
- دورة موافقة على التسجيل والاعتراف.
- أدلة جودة ونزاهة ومخاطر قابلة للتتبع.
- شهادات قابلة للتحقق علنًا عبر رمز تحقق.
- مسار مستقل للتدريب الميداني (فرص، حضور، تقييمات، خطابات إتمام).

**الثقة:** Strong inference من الميزات والكود؛ نية المنتج التجارية التفصيلية غير مُوثَّقة كعقد عمل داخل المستودع.

## 4. أهم الميزات

1. تسجيل طالب ذاتي + OTP بريد + تفعيل إداري.
2. إدارة المسارات والشهادات المصغّرة والمجموعات (cohorts).
3. الحضور والتقييمات والدرجات والأدلة.
4. ضمان الجودة والإجراءات التصحيحية وحالات المخاطر/النزاهة.
5. طلبات الاعتراف الأكاديمي والمستندات.
6. إصدار الشهادات والتحقق العام.
7. مقررات LMS مستقلة مع سير عمل درس تدريبي (قد يشمل AI).
8. وحدة تدريب ميداني كاملة (أكبر كتلة API في المشروع).
9. لوحات تحليلات وتقارير وتصدير PDF/Excel.
10. واجهة ثنائية اللغة (عربي/إنجليزي) وبوابات حسب الدور/النطاق الفرعي.

## 5. كيف بُني النظام؟

مستودع **متعدد التطبيقات (ليس monorepo بحزم مشتركة منشورة)**:

- **Frontend:** React 18 + Vite 5 SPA، React Router 6، TanStack Query، Axios، i18next، SCSS + Tailwind (للاندنج).
- **Backend:** Node.js + Express 4، Prisma 6، PostgreSQL، JWT، Zod، bcrypt.
- **النشر الظاهري:** واجهة ثابتة (`lms.battechno.com`) + API منفصل + PostgreSQL (Neon/غيره) — وفق `docs/DEPLOYMENT.md`.

## 6. كيف تتدفق البيانات؟

```
المستخدم → صفحة React → hook/service → Axios (Bearer JWT)
  → Express (/api/auth أو /api/v1) → middleware (auth/roles/validate)
  → service → Prisma repository → PostgreSQL
  → JSON response → تحديث UI (Query cache)
```

أحداث داخل العملية (`dispatchAppEvent`) تُنشئ إشعارات داخل التطبيق وسجلات تدقيق دون طوابير خارجية.

## 7. الأدوار الرئيسية

ثمانية أدوار مُبذورة: `super_admin`, `program_admin`, `university_admin`, `academic_admin`, `qa_officer`, `instructor`, `student`, `university_reviewer`.

## 8. أهم واجهات البرمجة والتكاملات

- **~330** نقطة نهاية REST تحت `/api/auth` و`/api/v1` (**Confirmed** بعد عدّ 327+3 في التحقق الثاني).
- أنماط استدعاء الواجهة ~**294**؛ فجوات مؤكدة في كتابة submissions/grades الأكاديمية من SPA.
- أكبر الوحدات: التدريب الميداني، المقررات، التحليلات، التسجيل، التقييم.
- **تكاملات:** Resend (بريد)، Gemini/OpenAI (AI اختياري)، Cloudflare R2 / تخزين محلي، YouTube Data API، Puppeteer (PDF)، ExcelJS.

## 9. أهم المخاطر التقنية

1. جدول `permissions` موجود لكن **غير مُبذور**؛ التفويض الفعلي عبر قوائم أدوار في `env` — خطر انحراف FE/BE.
2. JWT في `localStorage` بدون إبطال خادمي عند logout.
3. وحدة التدريب الميداني كبيرة ومعقّدة؛ تغطية الاختبارات جزئية مقارنة بالحجم.
4. صفحات lazy مُعرَّفة وغير مربوطة بالموجّه (QA/Risk CRUD وغيرها) — احتمال واجهة ناقصة أو مسارات مخفية.
5. اعتماد اختياري على مفاتيح خارجية (بريد/AI/R2) يجعل بعض الميزات «صامتة» إن لم تُضبط.

## 10. ما الذي يبقى مجهولًا؟

- تفاصيل اتفاقيات الجامعات ومتطلبات الاعتراف الرسمية خارج الكود.
- بيئة الإنتاج الفعلية (Render؟ مضيف آخر؟) — مؤشرات فقط في الوثائق.
- ما إذا كانت صلاحيات `permissions` ستُفعَّل لاحقًا أم مهجورة عمدًا.
- اكتمال بعض صفحات الإدارة (create/edit لـ QA/Risk) مقابل واجهات قائمة فقط.
- هل تسليم/تصحيح التقييم الأكاديمي (غير التدريب الميداني) مكتمل في منتج الواجهة أم API-only — فجوة FE مؤكدة في التحقق الثاني.
- سياسات الاحتفاظ بالبيانات والنسخ الاحتياطي التشغيلية غير ظاهرة في الكود.
