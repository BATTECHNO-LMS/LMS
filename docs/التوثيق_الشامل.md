## 1. نظرة عامة

### ما هو النظام؟

BATTECHNO LMS منصة ويب لإدارة دورة حياة برامج الشهادات المصغّرة من التصميم حتى الإصدار والاعتراف الأكاديمي. يشمل:

| المجال | الوصف |
|--------|--------|
| **المنهج** | مسارات → شهادات مصغّرة → وحدات → محتوى → مخرجات تعلم |
| **التنفيذ** | دفعات → تسجيل طلاب → جلسات → حضور |
| **التقييم** | تقييمات → معايير (Rubrics) → تسليمات → درجات |
| **الجودة** | أدلة → مراجعات QA → إجراءات تصحيحية → مخاطر ونزاهة أكاديمية |
| **الاعتماد** | طلبات اعتراف جامعي → شهادات رقمية قابلة للتحقق |
| **كورسات مستقلة** | إدارة كورسات مع دروس وتدريب تفاعلي (للمشرف الأعلى) |
| **تدريب ميداني** | فرص تدريب → طلبات → مهام → تسليمات |

### هيكل المستودع

```
LMS/
├── backend/     ← واجهة API (Node.js + Express + Prisma)
├── frontend/    ← تطبيق الويب (React + Vite)
├── docs/        ← التوثيق
└── .github/     ← CI/CD
```

### عناوين الإنتاج (من الكود)

| الخدمة | العنوان |
|--------|---------|
| الواجهة الأمامية | `https://lms.battechno.com` |
| API | `https://lms-7txx.onrender.com` (مرجع في إعدادات المشروع) |

## 2. البنية التقنية

### الواجهة الخلفية (Backend)

|--------|---------|
| وقت التشغيل | Node.js 18+ (يفضّل 20) |

**بادئات API:**
- `/api/auth` — تسجيل الدخول والتسجيل
- `/api/v1` — جميع وحدات النظام

## 9. سير العمل الرئيسي

### 9.1 دورة الشهادة المصغّرة

```
تصميم المنهج          التنفيذ              التقييم           الاعتماد
────────────          ───────              ───────           ────────
مسار (Track)    →    دفعة (Cohort)   →   تقييمات      →   طلب اعتراف
  └ شهادة مصغّرة       └ تسجيل طلاب        └ تسليمات         └ شهادة
      └ وحدات              └ جلسات             └ درجات
          └ محتوى              └ حضور
```

### 9.2 تسجيل الطالب

```
1. الطالب يزور /register
2. يختار جامعة ويدخل بريداً يطابق نطاق الجامعة (مثل @batuni.edu)
3. يُنشأ حساب بحالة inactive
4. الإدارة تفعّل الحساب (PATCH /users/:id/activate)
   أو تفعيل جماعي (POST /users/activate-pending)
5. الطالب يطلب التسجيل في دفعة
6. المراجع/الإدارة يوافق أو يرفض
7. الطالب يُسجَّل في الدفعة ويبدأ التعلم
```

### 9.3 التقييم والدرجات

```
المدرب/الإدارة ينشئ تقييماً → يربطه بمعيار (Rubric) اختياري
        ↓
الطالب يُسلّم عمله (ملف / رابط / نص)
        ↓
المدرب يقيّم ويُصدر درجة وملاحظات
        ↓
إمكانية إنهاء الدرجة (finalize)
```

### 9.4 أنواع التقييمات

| النوع | الكود |
|-------|-------|
| اختبار قصير | `quiz` |
| واجب | `assignment` |
| معمل | `lab` |
| امتحان عملي | `practical_exam` |
| مرحلة | `milestone` |
| مشروع تخرج | `capstone_project` |
| عرض تقديمي | `presentation` |

### 9.5 الجودة والمتابعة

```
مراجعة QA → إجراء تصحيحي (إن لزم)
حالة مخاطر للطالب المتعثر
حالة نزاهة أكاديمية (انتحال، غش، ...)
رفع أدلة للاعتماد
```

### 9.6 الاعتراف والشهادات

```
إكمال البرنامج → إصدار شهادة برمز تحقق
        ↓
طلب اعتراف جامعي + مستندات داعمة
        ↓
المراجع يراجع الطلب
        ↓
التحقق العام: /verify/certificate/:code
```

### 9.7 الكورسات المستقلة (مشرف أعلى)

```
إنشاء كورس → أقسام → دروس → إعداد تدريب
        ↓
ربط بالدفعات (اختياري)
        ↓
الطالب: بدء الكورس → إكمال دروس → تسليم تدريب
```

### 9.8 التدريب الميداني

```
المشرف الأعلى ينشر فرصة → الطالب يتقدّم
        ↓
مراجعة الطلبات → تعيين مهام
        ↓
الطالب يُسلّم المهام
```

## 10. المصادقة والتسجيل

### تسجيل الدخول

- `POST /api/auth/login` — يُرجع JWT
- التوكن يُخزَّن في المتصفح ويُرسل مع كل طلب: `Authorization: Bearer <token>`
- مدة الصلاحية: `JWT_EXPIRES_IN` (افتراضي 7 أيام)

### محتوى JWT

```json
{
  "userId": "uuid",
  "roles": ["program_admin"],
  "universityId": "uuid",
  "isGlobal": false
}
```

`isGlobal: true` للمشرف الأعلى — يتجاوز جميع قيود الأدوار في API.

### التسجيل الذاتي للطالب

- `GET /api/auth/register/universities` — الجامعات المتاحة
- `POST /api/auth/register` — إنشاء حساب طالب
- ربط تلقائي بالجامعة عبر نطاق البريد (`university_email_domains`)

### تسجيل الخروج

- `POST /api/auth/logout` — إقرار من الخادم
- حذف التوكن من المتصفح (جانب العميل)

### الصلاحيات

| الطبقة | الآلية |
|--------|--------|
| **API** | `authorizeRoles()` + متغيرات بيئة `*_ROLE_CODES` |
| **واجهة** | `RoleBasedRoute` + `permissions.js` + `RoleShellPermissionOutlet` |

> صلاحيات الواجهة تتحكم بالظهور فقط؛ الحماية الفعلية في API.

## 13. التثبيت والتشغيل المحلي

### المتطلبات

- Node.js 18+
- PostgreSQL
- npm

### 1. الواجهة الخلفية

```bash
cd backend
npm install
```

أنشئ `backend/.env`:

```env
NODE_ENV=development
PORT=4000
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DB?sslmode=require
JWT_SECRET=سر-محلي-32-حرف-على-الأقل
CORS_ORIGINS=http://localhost:5173
```

```bash
npm run prisma:migrate
npm run seed
npm run dev
```

يعمل على `http://localhost:4000`

### 2. الواجهة الأمامية

```bash
cd frontend
npm install
```

أنشئ `frontend/.env`:

```env
VITE_API_BASE_URL=http://localhost:4000
VITE_APP_ORIGINS=http://localhost:5173
```

```bash
npm run dev
```

يعمل على `http://localhost:5173` — يوجّه `/api` تلقائياً للخادم الخلفي.

### حل المشاكل الشائعة

| المشكلة | الحل |
|---------|------|
| خطأ Prisma P1001 | انتظر بضع ثوانٍ (Neon cold start) وأعد التشغيل |
| CORS | أضف أصل الواجهة في `CORS_ORIGINS` |
| 401 | سجّل دخولاً جديداً |
| تغيير `.env` في Vite | أعد تشغيل `npm run dev` |
