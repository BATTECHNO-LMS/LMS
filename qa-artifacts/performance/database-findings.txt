Measured (production /health vs /health/ready, keep-alive warm samples):
- /health (no DB): p50 106ms, min 104ms, max 362ms (first sample cold)
- /health/ready (prisma $queryRaw SELECT 1): p50 613ms, min 603ms, max 1251ms
- Steady-state extra cost of SELECT 1: ~500ms (ready p50 minus health p50)
- All 8 ready probes returned database: connected
- No 503 not_ready in the sample

Interpretation:
- This is NOT a down database. It is a high round-trip database.
- A single Prisma query costing ~500ms will make any sequential query chain feel like a hang.
- Auth middleware runs several Prisma queries on every authenticated request (see currentAuthContext.js).
- Prisma defaults in compose: PRISMA_CONNECTION_LIMIT=25, PRISMA_POOL_TIMEOUT=20, connect_timeout 15s
- Pooler detection: host matching -pooler. sets pgbouncer=true
- withDbRetry 3 attempts can multiply a slow/failing query
